# 评审窗口、站内预警与公开数据缓存

更新：2026-09-30。评审窗口/超时预警来自需求基线 B-03；提前24小时、延期权限、历史通知策略和30秒统计延迟为本次确认的产品规则。本轮不增加备份界面、消息队列或独立调度平台。实际验证见[本轮记录](../verification/review-cache-2026-09-30.md)。

## 评审时间窗口

- 分配任务默认立即开始，截止时间由开始时间加稿件冻结的评审期限计算；也可设置未来开始和明确截止时间。界面使用北京时间，接口传递 ISO 时间，后端规范为 UTC。
- 评分区间为 `[startsAt, dueAt)`；开始前和到达截止时间后都由服务端拒绝评分。前端以服务端 `canScore` 为准，失败后刷新状态并保留评分草稿。
- 所属地区运营或全国运营可以调整未完成任务。开始前可修改两端时间；开始后只能将截止时间延长到未来。调整必须填写5–2000字原因，不能改动已完成/已取消任务。
- 调整保留专家、稿件版本与 WarmFlow 节点，递增窗口版本，记录操作人、原因和前后时间；专家收到包含调整原因的站内消息。窗口内部操作历史不投影给专家。

## 自动提醒与查看入口

后台“评审管理”中查看任务窗口、调整时间和“评审预警”；右上角个人提醒入口可以定位对应任务。专家用户端从个人消息进入专家任务，查看北京时间和评分资格。

- 已开始且距截止不足24小时：每个窗口向专家提醒一次。
- 首次逾期：分别向专家与任务记录的负责运营通知一次；不向已停用或失去对应权限的账号发送。
- 上线已有逾期任务、提醒关闭后重新开启时已有逾期任务：只进入预警列表，不补发历史通知。延期后重新计算当前窗口。
- “系统设置→评审提醒”控制自动提醒。关闭提醒不关闭时间校验或预警列表，也不阻止显式调整窗口的通知。
- 每60秒扫描，批次200条，每轮最多处理30秒后继续下轮。任务、窗口版本、阶段、接收人构成投递唯一键，通知及投递记录在同一 MySQL 事务中写入；重启和多实例共用该账本。恢复时仅发送当前适用阶段。

新增 `GET /api/v1/admin/review-alerts` 支持页码、每页数量、临期/逾期、本人/权限范围和未读筛选；后台命令增加 `updateReviewWindow`、`markReviewAlertRead`。通知使用 `sourceType=review-task` 和 `targetId` 定位任务。完整字段以 [OpenAPI](../../contracts/openapi.yaml) 为准。

## 公开缓存与私人数据

`/api/v1/workspace` 仍返回原有业务分区。后端先取得公开目录与统计，再按当前身份添加私人记录；命令事务内完全绕过共享缓存，读到本次写入结果。

| 数据 | 策略 |
| --- | --- |
| 公开首页配置、轮播、作品和内容目录 | 最长300秒；发布、撤回与相关配置更新后切换版本；轮播开始/结束时间提前终止缓存 |
| 首页总量、公开媒体互动数、公开活动报名数 | 最长30秒，从构建开始计时，不续期旧统计；首页保留 `asOf` |
| 私人作品、收藏关系、消息、评审任务与后台工作区 | 按当前身份读取，不写共享缓存 |
| 报名容量、评分资格及其他写入校验 | 数据库实时校验 |

首页采用数据库 COUNT/DISTINCT，媒体互动和活动报名采用批量 GROUP BY。公开目录读取使用状态过滤和索引，不再逐条扫描互动列表。

缓存键含环境、格式版本、数据库 epoch 和内容版本。相关写入在业务事务中同步修改版本，缓存前后检查版本；连续变化导致无法获得一致内容时返回可重试错误。Redis 单次业务缓存操作从派发到响应最多等待100毫秒、零重试；使用最多8个不排队的后台线程限制同步派发阻塞，超时或资源耗尽即回源；故障后短暂绕过缓存并回源数据库，同进程合并相同缓存构建。该降级仅针对公开缓存，登录会话仍依赖原有 Redis 机制。

`JIAFENG_PUBLIC_CACHE_ENABLED=false` 可禁用公开缓存；Compose 用项目名隔离缓存命名空间。日志 `Public projection cache counters` 提供命中、未命中、构建、版本重试、Redis 故障计数与调用耗时。无需清空 Redis，会话配置保持不变。
