# 本机真实后端与后续开发

更新：2026-09-26。本文说明本轮实际代码，验证结论集中于 [后端验证](../verification/backend-runtime.md)。PDF 是完整需求基线；用户本轮确认的本机开发范围优先于原文远期计划。

## 运行入口

从仓库根目录执行 `./deploy/dev up`。首次自动生成仅本机可读、Git 忽略的随机凭据，构建 Java 与两端，初始化数据库和私有桶，等待应用迁移完成后开放入口。

- 用户端 H5：`http://127.0.0.1:18080/`
- 后台：`http://127.0.0.1:18080/admin/`
- API：`http://127.0.0.1:18080/api/v1`
- 私有 S3 下载入口：`http://127.0.0.1:18333`，授权下载地址五分钟有效。
- 数据库、Redis、存储管理端不发布到宿主机；默认应用和下载端口仅绑定回环地址。

开发账号 `devadmin`、`region_zj`、`region_bj`、`expert_zj`、`member_zj`、`member_bj` 共用本机生成的开发密码，保存在 `deploy/.env` 的 `JIAFENG_DEV_PASSWORD`。分别验证全国管理、浙江/北京运营、浙江专家、两地投稿人。密码不写入源码或文档。关闭开发账号登录开关后，不会偷偷开放一个生产登录入口；微信登录尚待实现。

局域网访问需同时配置绑定地址和客户端可达的 S3 端点，校园网设备隔离可能仍阻止互访。完整配置、停止、日志、备份和新卷恢复步骤见 [部署说明](../../deploy/README.md)。本项目使用独立 Compose 项目和数据卷，不占用原有 5173 或接管其他项目。

## 工程与复用边界

`apps/server` 保留固定若依提交 `de394a0e21f1e0648ef229d027c3a927d98200a2` 的模块结构与 LICENSE；Java 21、Spring Boot 4.1.0、WarmFlow 1.8.9 沿用完整上游组合。运行入口去除默认 AI、MCP、示例、外部任务调度、监控客户端，不启动消息队列或搜索引擎。完整引入范围和镜像 digest 见 `source-lock.json`、`apps/server/UPSTREAM.lock.json` 和 `deploy/images.lock.json`。

家风业务位于 `ruoyi-modules/ruoyi-jiafeng`。认证复用若依 `LoginHelper`、Sa-Token、Redis 会话与 BCrypt；开发账号使用 `sys_user`。现有后台按需适配 plus-ui 的 token、请求、登录和权限生命周期，保持既有界面。若依自带角色、菜单、字典、日志、文件模块保留；家风的地区授权、岗位权限和业务词库在独立模块实现。所选提交**没有可直接使用的租户模块**，当前也没有物理省库。

WarmFlow 实际保存定义、实例、节点任务和办理轨迹。家风模块负责不可变稿件版本、匿名材料、专家分配授权、评分、人工结果与公开发布。配置发布后以 `flowVersion` 建新定义；既有实例引用冻结配置，不用前端进度数组冒充引擎。

上传复用若依 OSS 客户端与其 AWS SDK。上游自定义域名模式面向绑定桶的域名，本机 S3 网关需保留桶路径，因此下载用同版本 SDK 单独配置客户端可达端点签名。内部上传与外部下载地址分开，禁止通过替换已签名 URL 的主机名实现转换。

## 业务模块与状态

| 范围 | 实际服务行为 |
| --- | --- |
| 投稿、用户 | 本人云草稿，ETag 并发控制，multipart 附件，幂等提交，初审、退修、新版本重投；后台账号岗位、停用、审批 |
| 评审、专家 | 运营确认脱敏正文；专家只读分配材料，不能下载原附件；四维 30/30/25/15、窗口校验、重复评分拒绝；管理员决定结果并独立控制公开 |
| 内容、典籍 | 中文/英文内容分别保存与发布，下架立即退出公开接口；卷章编辑、排序、已公开入选稿件导入、入藏发布；编辑章节后回到编纂状态 |
| 活动 | 发布报名、取消、唯一报名、名额事务、人工推进及签到台账 |
| 教育 | 课程编辑和上架、实际章节阅读记录与完成台账；当前后台表单将描述保存为导读章节，不虚构多章内容或测验结果 |
| 公益 | 商品、单次额度、申领、审核、退回、发放；申领归商品履约地区，运营同时校验申领和商品地区；发放事务锁库存，重放幂等键不重复扣减 |
| 运营 | 工作台与智库按授权业务记录统计，CSV 从同一授权集合导出；系统配置、通知草稿与真实站内发送、已读记录、操作日志 |
| AI | 私有资料上传、词库管理、权限和实际记录查询；没有模型请求时日志为空；资料显示未索引，不宣称具备推理或检索能力 |

作品 `status` 是处理状态，`decision` 是人工评审结果，`published` 是公开开关。高分不自动入围，不自动公开。版权勾选记录版本和确认时间，但不是正式电子签章。后台数据中的「验收」「联调」记录由本轮测试创建，属于开发测试记录，不是运营成果。

评审默认六节点，可启停；至少开启一个节点。本期固定匿名评审；HTTP 界面不提供非匿名切换。入口的收件审核建立流程；如果流程启用了初审节点，则此动作办结该节点，其他节点交由手工分配和专家提交推动。超过窗口的任务拒绝评分，可由运营重新分配；旧任务保留且失效。匿名正文须人工检查确认，系统不声称自动脱敏有效。

## 数据模型与事务

采用 MySQL 8.4.9。初期为了敏捷扩展，`jf_entity` 为多种业务提供独立记录：`kind / owner_id / region_id / status / version` 为索引列，业务字段为按领域校验的 JSON。它不是把整个前端工作区存成一个快照，也不是每类业务都有独立关系表。业务新增/变化集中在服务层；随着数据量和统计需求增长，可把高频领域迁出到专表，保持 HTTP DTO 不变。

另有实际独立表：账号授权 `jf_account`、唯一草稿槽 `jf_draft`、不可变稿件 `jf_revision`、文件元数据 `jf_file`、版本附件外键关联 `jf_revision_file`、活动报名 `jf_registration`、幂等响应 `jf_idempotency`、操作审计 `jf_audit`、登录限流 `jf_login_attempt`。协议版本与确认记录保留在不可变稿件数据中；独立签到实体记录实际签到时间，报名表保存签到状态。实体关系表的外键、版本号及报名唯一键与服务端事务共同工作。

业务写事务使用 READ COMMITTED，先锁定相关账户或实体，再校验并写入。这里需要在等待行锁后读取最新已提交的名额/任务记录，不能沿用事务开始时的旧快照。幂等键按账号、动作隔离，同键不同内容拒绝；重放只复用操作结果，工作区按当前权限重新构造。草稿和已有记录另有乐观版本校验。

迁移在应用启动时获得 MySQL 命名锁，按顺序执行版本 SQL，并保存 SHA-256。已执行文件不允许改写。V001 建业务表；V002 建版本附件外键并回填已有版本。迁移 SQL 支持中断后重试，迁移完成前 health 不返回 `status:ok`。后续修改增加新 SQL 文件并登记顺序，不修改旧迁移。

## 服务边界与两端

[OpenAPI](../../contracts/openapi.yaml) 对应当前 `/api/v1` 实现。公开/本人工作区、后台工作区、专家脱敏任务有不同字段；列表、详情、写入、下载与统计均执行后端授权。客户端地区筛选不能扩大集合。专家后台也不能取得原稿正文和文件。

两端 `VITE_DATA_MODE=http` 启用异步服务，Compose 构建默认使用此模式。未启用时仍保留原有演示模式，设备演示数据不会迁入数据库。请求错误、会话失效、冲突均显示真实结果；服务失败不会回退成演示成功。草稿提交得到确认后才清理编辑状态。

当前聚合工作区适合本机试点：尚未分页，统计由服务端授权记录在后台聚合。不能据此宣称全国容量、海量导出或查询性能验收完成。下一步优先把高频列表/导出迁为分页和服务端聚合，保持现有 service 边界。
