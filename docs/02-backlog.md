## 6. 迭代组织建议

1. **先确认页面与路径**：P0-01/02/04/09 优先形成演示；观察用户能否理解内容入口、投稿状态和运营动作。
2. **再补关键反馈**：补齐草稿、收藏、报名、AI 示例和专家评分；统一 loading、empty、error、success 状态。
3. **评审后收敛真实闭环**：基于演示反馈调整字段与流程；解决 Q-02/03/04/09 后，再拆后端任务和数据迁移。
4. **开源复用进入每个故事**：记录来源版本、许可证、保留声明、依赖风险、改动边界及维护责任；组件能解决的不用整套业务系统替换，已有后台能力按适配成本复用。
5. **每轮只扩大已验证范围**：未完成模块以明确的待建设状态展示；不通过伪造成功反馈代替功能交付。

建议每轮结束记录：已验收故事、用户反馈、需求变更、待决问题、下一轮优先项。故事规模和团队能力确定后再估工期。

## 7. 当前演示验收脚本

以下是目标验收流程，执行时应记录通过/失败/未实现，不提前填成“通过”。

| 路径 | 检查点 |
| --- | --- |
| 首页 → 地区 → 搜索 → 内容详情 | 导航明确；地区状态可见；搜索成功/空结果都有反馈；详情可返回 |
| 投稿 → 缺字段 → 保存草稿 → 恢复 → 模拟提交 → 个人作品 → 进度 | 校验、持久化范围、提交状态、记录一致；六级示意标签可见 |
| 典藏 → 筛选 → 详情 → 收藏 → 个人收藏 | 收藏状态一致；重复操作结果可理解 |
| 传习 → 活动详情 → 模拟报名 → 再次点击 → 个人活动 | 不重复新增；有模拟提示；记录一致 |
| AI 助手 → 输入 → 示例回答 | 可操作、等待反馈、示例标记；不收集敏感数据、不声称真实推理 |
| 管理工作台 → 筛选稿件 → 详情 → 状态操作 / 专家评分 | 处理反馈可见；评分值合法；不会被理解为正式审核决定 |
| 手机窄屏 / 桌面 → 各主页面 | 无遮挡和关键溢出；导航、表单、按钮可用 |
| 重置演示 → 刷新 | 示例可重新开始；本地数据范围明确 |

## 8. 进入下一阶段前必须补齐的输入

- 首批试点地区、运营组织与内容负责人；正式品牌与可用内容素材。
- 投稿字段、作者与投稿人关系、作品授权、附件大小与体裁规则。
- 最终评审层级、角色、评分、晋级、退回/撤回/异议处理方式。
- 租户和地区对应关系、物理分库与全国同步数据边界。
- 登录/实名、公开字段、未成年人和海外用户的实际处理流程。
- AI 私有化预算、网络条件、模型与知识素材许可、首批可验收任务。
- 正式语言清单、翻译审校方式、各阶段平台与交付验收范围。

这些输入不妨碍当前 P0 前端原型推进，但会影响真实业务上线方案与排期。
